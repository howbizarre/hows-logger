# Как работи Cloudflare Tail Worker-ът `hows-logger`

`hows-logger` е Tail Worker, който приема логове от други Cloudflare Workers чрез вградената Tail функционалност на платформата. Работникът няма зависимости към външни услуги и служи като централизирана точка за оглеждане на събития, излъчени от други приложения.

## Основен поток на обработка

1. Cloudflare доставя пакет от trace събития до Tail Worker-а.
2. Работникът проверява дали има събития за обработка. Ако пакетът е празен, функцията приключва без допълнителни операции.
3. За всеки trace запис се извършват последователно следните стъпки:
   - Извлича се резюме (изпращащ скрипт, резултат от изпълнението, брой логове, изключения и диагностични събития) и се отпечатва като JSON.
   - Всеки лог запис (`console.log`, `console.error` и др.) се форматира до унифициран JSON и се записва в `console.log`.
   - Изключенията се форматират отделно и се извеждат през `console.error`.
   - Diagnostic channel събитията се нормализират и също се записват в `console.log`.
   - Ако trace записът съдържа допълнителни данни за събитие (например HTTP заявка), те се сериализират безопасно и се записват като `event_info`.
4. След обработката на целия пакет се логира обобщаващо съобщение с броя обработени събития.

## Защо структурата е полезна

- **Еднообразни JSON записи** – всеки тип събитие се форматира по идентичен начин, което улеснява последващото индексиране или филтриране.
- **Безопасна сериализация** – комплексни обекти (като Request или Response) се сериализират с защита срещу циклични референции; при невъзможност се отбелязва, че данните са несериализируеми.
- **Разграничение по канали** – нормалните логове се изпращат през `console.log`, докато грешките се насочват към `console.error`, което улеснява мониторинга.
- **Минимални зависимости** – Tail Worker-ът не използва външни API-та или бази данни, което намалява възможните точки на отказ.

## Структура на проекта

```
src/
 ├─ index.ts  → основната Tail функция и помощни хелпери
 └─ types.ts  → описания на Trace типовете и формата на нормализираните записи
docs/
 └─ TAIL_WORKER_OVERVIEW.md → текущият документ
```

## Наблюдение на логовете

След като Tail Worker-ът е свързан към други приложения, можете да наблюдавате логовете директно в Wrangler:

```bash
wrangler tail --service <име-на-приложение> --tail-worker hows-logger
```

Командата ще показва JSON записите, които `hows-logger` генерира, което улеснява дебъгването и анализирането на поведението на вашите Worker-и в реално време.
